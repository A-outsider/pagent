# 恢复与试跑经验

仅在对应问题出现时读取相关部分。这里记录已证实限制和操作恢复，不修改 Pagent 源码，也不建立第二套浏览器包装层。说明基于 2026-10-03 本机版本，工具升级后以实际 schema 与结果为准。

## 动态控件：先读结果，再决定下一步

| 现场情况 | 最小恢复 |
| --- | --- |
| `找不到选项`，但控件能展开 | 先在一个样本读取真实枚举，核对词义后转换目标值，再批量复用；不要把同一原值在其余页面继续试一遍，也不先更换点击方式。已证实例子：省级→省区级、校级→院校级、CET-6（六级）→六级。学习形式在不同公司可能分别是“统招全日制”或“全国普通高等院校全日制”，同一渲染器不保证同一枚举。熟悉→熟练等能力升档没有同义依据，不套用这种转换。 |
| 动态下拉选项点击后报“找不到元素” | 先读常驻字段值或变化。选项可能已被 React 卸载而操作成功；不重试旧节点。确实未选中时重新定位真实选项，用 `click_element` 点击，再核验字段。 |
| `choose-option` 报“选项上下文未打开” | 检查弹层是否已展开；有选项时直接定位实际选项，不再次开关同一输入框。仍找不到有据选项就留待核对，继续其他字段。 |
| 只读日期字段不能写值 | 先从实际 placeholder、输入格式或日历视图确认只收年份、年月还是完整日期，再按来源转换并正常选取；不轮流试写三种格式。同模板复用已确认的粒度。某页奖励时间只收 `YYYY`，传年月日会被清空，不能误当模型漏填。不强写 readonly input、不改框架状态。 |
| 自定义下拉的核验组件不支持 | 保留当前正确值，记“页面已见值、核验未支持”，从排障队列移出；不能为了拿到 verified 清空重填。若已有支持的常驻选中节点，可在剩余预算内随本批独立核验，不能展开额外探测链路。临时菜单选项或搜索输入文字不能证明提交值已选中。 |
| 新增/删除经历后 ID 被复用 | 重新扫描关联记录，按身份绑定当前控件。旧 ID 相同不代表仍属于原记录。 |
| `scope:interaction` 抓不到实际弹层 | 新版显式局部观察返回空层状态；先确认是否已收起，再做一次定向文本搜索。确需页内查找才主动用 `scope:page`，只读相关范围，不把整页分页当成弹层选项。`maxElements:200` 不保证一页返回 200 个。 |
| 数值一样、显示多了 `.0`，却核验 mismatch | 明确的原生 number 字段应按数值等价核验，保留实际回读格式；不因格式差异重写。手机号、证件号和编号等文本仍严格比较，不全局去零或转 Number。 |
| 城市/职业文字点了，确认后字段仍空 | 区分分类展开与最终选择。当前菜单内定位关联的真实 radio/checkbox，检查 checked；没有选中证据的 anchor 点击只算导航。组合显示值还需核对来源和常驻字段，不为消除 mismatch 直接抄页面。 |

已经观察到正常控件，但结构化操作不支持时，可在工具允许范围内对该控件使用 DOM/CDP 点击作为局部后备。先读取 `execute_cdp_script` 等实际 schema；只能操作现场已确认的 DOM 目标，随后回读。不要修改 React/Vue 内部状态、请求内部写接口，或绕过上传与提交保护。不为一处失败编写全站脚本。

一次有依据的恢复仍未推进就记录该控件，先完成其他内容；尾查可凭新增证据补齐。不存在“所有控件必须成功才能继续”的门槛。

执行预算和跨页延后规则以 SKILL.md 第 0 节为准。首轮盘点全部栏目与来源记录，时间不足的项保留“尚未处理”；先完成全部页面可直接填写的内容，再进入独立计时/计次的集中难项阶段；主填耗尽不永久封锁难项。最后检查全部来源记录，补普通遗漏。来源未知项不随反复扫描重新入队。不要把“完成度优先”理解成无限耗在同一控件，也不靠预算掩盖遗漏或将“已尝试”算作“完整”。

## 北森 Phoenix 控件：2026-10-04 的确认结果

金证页面的民族弹层中，脚本调用文字、整行或图标的 `.click()` 后，radio 仍未选中。使用 Pagent 官方 `execute_cdp_command` 的 `Input.dispatchMouseEvent` 对当前可见图标发送 mousePressed/mouseReleased，再点击当前“确定”，独立核验返回 `stable:true`、`satisfied:true`；政治面貌普通选项用同样鼠标事件也核验通过。仅适用于现场确认相同结构的控件，不推断所有网站都需要原生鼠标事件。

- 自定义列表实际选项是 `.list-item-container` 内的 radio 图标；普通列表是 `.phoenix-selectList__singleLabel`。先辨认当前弹层类型，不把两者套成同一选择器。
- 后台表单控件可能在视口外。`getBoundingClientRect().height > 0` 不表示可点击，本轮曾读到选项纵坐标为负数。先把已绑定的字段 `scrollIntoView`，重新读取视口内的目标坐标，再执行鼠标事件；滚动目标标签不要求切换用户前台窗口。
- 下拉开合只用于定位；以常驻值和独立回读证明写入。原生点击仍未推进就按累计预算延后，不在每家公司重复调试。

本轮另一处误判发生在朴朴栏目保存：点击后立即观察仍有编辑框，稍后的独立观察已出现“编辑”按钮及保存后的正文。没有明确失败回执时先给一次短暂稳定等待再回读，不马上重新填整条记录；等待也计入页面预算。

## 来源转换与核验账本

`sourcePath` 直接引用原始叶子。工具会拒绝同时传入与原值不同的 `value`；转换只传 `value`，另保留来源与转换理由。例如日期控件只收年月，按源日期选年月，回读展示可能还附年龄，使用真实展示格式作为当前核验预期。

预期值不能只抄页面。网站“掌握程度”的 **良好** 与来源 **日常会话** 需要真实枚举及语义映射依据；字面回读通过不证明来源一致。精确选项存在就用精确选项；没有合理映射时记待确认，不能用 CET-6 自动推导任意等级。

核验账本保留各字段最后一次相关修改后的证据：菜单开合、Escape、明确只读 CDP 不全表失效；普通写入只使对应字段 pending，局部记录新增/重建只使受影响记录及依赖失效；文档替换或 PDF/牛客广泛回填才重建整表基线。同值 `set-value` 与 `choose-option` 可沿用同一预期，但日期格式/语义或来源真正改变仍需明确转换。区分：

- 当前来源是否匹配、当前字段是否独立核验通过；
- 旧账本残留的 failed/pending；
- 真正仍未处理的来源记录。

不要为了清理计数伪造一次写入、隐藏字段或反复清空上下文。保留真实残留并说明；常规填写不为刷新统计结束重绑、重读来源或重新全表核验。明确排障需求才建立新快照，保留原操作历史、累计预算与调用数；新快照不会自动保存表单，也不能消除真实来源差异。

实现位置：`pagent/src/features/page/actions/batch-interact.ts`、`verify-fields.ts`，以及 `pagent/src/features/agent/runtime/resume-workflow.ts`。排障时再读取，不默认全仓审计。

## 上传不确定与连接异常

`prepare_resume_form` 返回歧义时优先使用其 `candidates/revision`，或扫描的 `upload.purpose/autoParse/receiptNames/assignedFileNames/inProgress` 定位。解析区用 prepare，独立正式简历区用 ensure；同名文件的回执不能跨区复用。

- `filesAssigned` 只表示文件赋值；网站显示接收回执和解析稳定是不同证据。`identity:unverified` 不要求为了哈希再上传，也不能宣称原件字节已经核验。
- 回执未知不等于解析仍在运行。只有明确的上传/解析进行中证据才有限等待，避免牛客和解析并发回填；限时后跳过牛客继续任务，观察到解析后变化时再定位和核对，不能无限轮询。
- 尚未赋值的明确目标在牛客前可定向补传；已赋值但回执不明只观察。牛客调用一旦开始，prepare 被直接接口禁用，失败的牛客也不恢复该入口。
- `ensure_resume_attachment` 会拒绝 parser、unknown、other、avatar；目标不是正式简历就不要尝试通用上传绕过。当前简历任务的 `upload_attachment` 仅允许头像。
- `list_attachments/get_attachment` 属于动态外部 MCP；确需发现附件时按返回名称/schema 使用。专用 prepare/ensure 对已知 PDF ID 自行取附件，省掉重复拉取。

连接不可用时先只读检查 Host 与扩展连接状态。本机 Host 默认 `127.0.0.1:17344`；重启服务后 Chrome 可能还保留旧 socket，2026-10-03 试跑通过重新加载 Pagent 扩展恢复。不要刷新招聘表单或要求重启整个浏览器；需要用户手动重载时说明现场依据，不把普通填写失败归因于 API key。直接模式不需要 Pagent 聊天网关。

## 本轮专项优化

这些优化落在执行方法，复用现有工具：

2026-10-04 的 12 页批次，曾结束的 12 个上下文累计返回 `toolCalls=1079`，其中金证单页 230 次；后续操作另计。这说明直接 MCP 虽省去 Pagent 独立聊天调用，仍会被 Codex 的诊断分支和重复核验拖慢，不能据此宣称提速。后续读清实际枚举并转换后，4 页奖励等级、3 处英语水平、LD 学历/学习形式与金证两处学习形式共 **15 个字段**补齐且独立核验通过。可复用的是“先核对真实枚举”，不是为每页更换多种点击方式。学校文本正确但选中证据不足、资料未知导致保存受阻，仍按未确认报告，不为改善统计重填。

| 主要浪费/遗漏 | 执行调整 |
| --- | --- |
| 两个 Agent 分别调用模型 | Codex 直接编排 MCP；不 dispatch，不把 SOP 再发给 Pagent。 |
| 同一简历反复读取、长字段反复复制 | 每任务读取完整最新来源一次；叶子用 sourcePath，只有格式/组合字段取原值转换。 |
| 每填一个字段重扫页面 | 阶段变化做整表扫描；稳定文本按 30 项内批写，控件变化看局部。 |
| 大量点击重试 | 先读实际选中值，动态选项用 click_element；出错不证明未发生。 |
| 只核验写过的少数字段 | 尾查按来源记录清单查覆盖，再核验所有适用已知字段，包括牛客回填。 |
| PDF 最后上传覆盖成果 | 上传解析前置，解析归属修正后再牛客；主填后不重跑解析。 |
| 准备/回执失败导致零填写 | 单项记失败继续；仅真正不可操作才停止该页。 |
| 不同读值都被算作节省 | 只报告实际工具计数和已证实效果，不推测 token 百分比或时间收益。 |

没有额外包装脚本、依赖、后台队列或网站专属适配器。常规填表由现有结构化工具完成；真实复现的产品缺陷需要修复时，再在共享实现处改一次并做对应验证。

## 傅利叶试跑：证据与边界

2026-10-03 的复杂申请表涵盖教育、3 段实习、1 个独立项目、语言、2 项奖励、自我评价。先上传 PDF，按最新分类规则把误解析为项目的两条内容归回实习，补齐职位与完整工作正文，再执行一次牛客及尾查。

结束上下文返回 **Pagent modelCalls=0、toolCalls=46**；61 个不同字段通过当前预期值的独立回读。这是单页直接上下文的计数，不能推断整项任务零 token、与 Pagent 的速度倍数或全部字段来源一致。

尾查同时发现：语言“掌握程度”映射尚缺枚举证据；生日旧预期及已移除项目留下账本残留。最后观察到城市与隐私项变化，但本轮没有相应写入动作；变更来源和网站保存/提交未确认。标签页随后不在列表中，停止该页，不重新打开。用户认可现场填写效果，后续 skill 保留上述边界，避免把好效果报告成无缺项。

原环境的临时验证记录未随分享包分发，不作为本 skill 的运行依赖；需要验证时使用本人的当前页面，不重建原作者的私人快照。
