# Pagent 网申填写

目标是尽量填完所有有来源且适用的内容，包括全部经历与附件。Codex 负责判断和编排，Pagent 负责执行；保持任务级 fail-open，单项失败不结束整轮。未知事实留空，默认停在待提交状态。

默认由 Codex 直接调用 Pagent MCP 主导操作，不通过 Pagent 聊天框发送任务指令，也不委派 Pagent 独立模型处理；只有用户明确要求委派时才切换该方式。MCP 故障不自动改用 Pagent 的 API key 调用。

本机资料规则先读 `__INSTALL_ROOT__/resume-mcp/AGENTS.md`；结构化来源为其 `data/resume.json`，每个任务通过简历 MCP 读取最新版本。不要把个人资料、附件字节、API key 或 Cookie 写进 skill。

Windows 分享版：牛客面板的自动打开依赖 macOS，Windows 由用户手动打开；未打开或辅助调用失败时继续普通填写，不阻塞任务。

## 0. 完成度优先：先覆盖，再排障

完成度按全部适用来源记录及字段统计，不能用“核验零失败”代替。未知事实不编造；单项失败只延后该项，不能挡住其他栏目或页面。

**下一步从待填队列选，不从最近报错选。** PDF/牛客各一次后，先完成全部页面可直接填写的内容，再集中处理延后的难项，最后做一次来源完整性检查。限时用于调度让路，不是阻止后续补齐的授权门槛。

| 优先级 | 实际操作 |
| --- | --- |
| 1 | 补齐全部缺失记录；批量填写已知必填文本、每条经历的名称、职位/角色与完整正文。不能只完善第一条。 |
| 2 | 用已证实方法填写有来源的日期、下拉、其他必填项和可选内容；同批部分成功就保留成功项，只接续失败与未执行项。 |
| 3 | 全部页面普通内容已处理后，按延后清单进入 review，集中处理难项；复用同模板已证实方法，主填耗尽项获得本阶段独立恢复窗口。 |
| 4 | 集中处理后做一次来源完整性检查，补普通遗漏并批量独立核验；不为刷新计数重复整表填写。 |

主填中仍有明确文本或完整记录尚未执行时，不排查可选控件、不逐字段独立核验、不查工具源码。必要栏目保存照常执行；添加记录失败只影响该记录，其他现有记录继续填写。明确误分类的局部清理仍须在解析核对后完成，失败继续其余来源内容。

### 执行预算

这些是处理过程中的默认让路阈值，不是要用满的配额，也不是整批任务的完成条件。主填与集中难项阶段分别计时、计次；主填超限只将该项放入延后清单，不能永久封锁它或要求用户另开任务。工具很快但判断、读取和反复诊断很慢时，同样计时。

| 范围 | 到界后的动作 |
| --- | --- |
| 本阶段失败控件实际恢复累计 45 秒或 3 次恢复调用无实际进展 | 延期该来源项，取下一待填项；混批继续其他项。全部普通内容完成后，集中难项阶段提供独立恢复窗口。 |
| 每页本阶段诊断累计 90 秒或 6 次调用 | 本阶段不再探索新方法，继续普通填写、必要定位、保存和首次批量核验；主填与集中难项分别累计。 |
| 同模板新方法探索累计 90 秒 | 成功则复用；失败不在后续公司重复探索。不同公司枚举仍需实际核对。 |
| 每页主填 5 分钟、集中难项及检查 3 分钟 | 限制当前页等待，保留成果和缺项并转下一页；全部普通内容处理后正常进入集中难项，不因主填超限结束整批。 |
| 当前页连续 2 分钟没有新增来源正确的字段、记录或保存成果 | 提前转下一页。 |

- 代码累计同申请页处于活动状态的工具等待和调用间判断时间，切页/结束暂停；重新绑定不清零。用 `get_resume_progress.executionBudget` 读取实际累计，不另造账本；全部页面普通主填后调用 `resume_execution_phase({phase:"review"})`，进入集中难项及来源检查。本阶段的恢复/诊断计数独立，原主填耗尽项保留作待办与历史；这是同一任务的正常推进，不另行索要用户确认。`resetResumeBudget:true` 只用于真正的新任务，或用户明确纠正策略、应用修复后继续现有缺项；不用于绕过同阶段无进展限制。模板探索及2分钟无进展转页仍由 Codex 调度，不能声称已由工具自动执行。整批总墙钟与无法绑定/零写入页面另行计入交付分母。
- 等待到期返回 `status:unknown`，本上下文隔离后续页面动作，只取进度并结束；已派发动作可能仍在完成，不能重发。预算跨上下文保留在扩展内存，重载扩展或进程重启不持久化。Codex保留原耗时、核验证据与延后清单；修复加载后从已有缺项继续当前阶段，不重跑已完成的PDF、牛客或普通字段，不将内存计数丢失说成未曾处理。
- 控件预算键为 `tabId＋来源记录＋字段语义`，诊断预算按页面/模板累计；方法、ID、上下文和同阶段会话续接不重置；主填进入集中难项时按阶段独立计数，累计总耗时和原缺项仍保留。每次调用前检查剩余时间与次数，结束即更新；一次包含多个内部动作的工具仍计实际墙钟时间，不能靠包装或重绑逃避预算。
- 实际进展是正确值保留、来源记录新增或保存回执变化。菜单展开、找到选项、重新扫描、换一种点击方式、重新绑定及重复报错只提供证据，不视为完成进展。普通首填、必要定位、栏目保存和首次批量核验不算排障调用。首次核验未写字段不可用不创建失败恢复状态；只累计当前实际恢复目标的诊断时间，处理其他字段不消耗它。定向恢复的搜索、读值、观察、CDP和重试算诊断，不能改名绕过同阶段上限。
- 到界先记录，再进入下一项；不能只提醒自己限时后继续尝试。当前工具还在运行时最多额外观察 30 秒、一次，未确认就记“运行结果未确认”，不取消/重发同一写入。其他页面可独立执行则继续；Host 全局串行队列受阻时停止浏览器重试，按完整队列报告。`busy/inProgress` 不延期。
- 保留的最小调度状态为：页阶段与起点、全部来源记录及适用字段、每项状态、累计时间/调用数、最后结果、再次处理所需证据。记录身份、日期、职位/角色、正文、成果分别统计；“已尝试”不代表完整。临时状态确需落盘时只用当前用户私有的系统临时目录（Windows 使用 `%TEMP%` 下禁止继承、仅当前用户与 SYSTEM 可访问的子目录），不保存个人值到代码仓或 skill。
- 尾查先检查未处理来源与缺失记录，补可执行遗漏；延后项在集中难项阶段按独立恢复窗口处理，凭实际控件/选项证据选择方法；成功方法复用，不无依据轮换。未知/冲突资料一次登记后不重新入队。组件核验不支持、显示格式差异或账本残留直接标记未核验；正确页面值不为刷新计数而重写。只有明确来源错误才做一次局部修正与受影响字段核验。

**不在单控件排障中扩建工具产品或创建新的浏览器执行层。** 已知方法失败先延后并完成其他内容；实际工具误拦截影响整批、且用户已要求纠正规则时，修最小问题后继续现有缺项，不把内部计数变成新的用户授权门槛。阶段限时后的遗漏必须保留并报告，不能当作已完成。

## 1. 绑定指定页面

- `mcp__pagent__list_tabs` 找到用户指定窗口与申请页，固定 `tabId`。用户已提交或关闭的页面不重开；标签从列表消失只表示当前不可用，不推断由谁关闭或已经投递。保持原窗口和标签组，不刷新表单、不重复开页、不抢前台。
- `browser_list_tools({tabId, prompt})` 建立上下文。prompt 用用户本次短指令即可，如“完整填写当前网申，未知留空，不提交”，不用把整份 SOP 发给 Pagent。
- 读取返回的 `toolNames` 和本轮需要的 schema，可用 `names` 缩小详情。外部简历工具可能带服务器前缀，使用现场返回的准确名称。
- 工具目录和来源键名首次确认后复用；只缺少 schema 时按 `names` 补读，不重复输出整个目录。同文档使用固定 prompt 和 `contextId`，不要为每个控件重新发现工具或结束重绑。
- 后续全部用 `browser_call_tool({tabId, contextId, name, args})`。排障附 `execution:{diagnostic:true,fieldIds:[...]}`，false 不绕过已识别的失败恢复预算。`status:deferred` 按返回动作转其他字段/页面；混批的 `status:partial` 读取 `executed` 和 `deferred`，不重发整批。同一页串行，多页先主填再尾查，不争抢正在运行的任务。
- 普通 DOM 更新沿用上下文，但重建的元素重新定位。换文档、刷新、扩展重载或设置变更后重新绑定。直接模式不调用 `dispatch_task`，不配置或调用 Pagent 聊天 API key。
- 简历上下文自动启用后台 focus emulation，结束时恢复，不需要用户切前台。`backgroundFocus:unavailable` 时继续普通工具；Host 的 `busy` 不表示断连。超时若已交扩展，先回读，避免重复执行仍在运行的写入。

## 2. 读取来源，先处理 PDF

一次 `get_resume({compact:true})` 取得本轮完整原始来源、`classificationRules`、`recordInventory`，主填和尾查复用。存在明确截断/省略标记时按栏目补读，不能用半截 JSON。用户中途更新资料时重新读受影响来源。

先确认实际键名再构造字段映射，不猜“公司名称”等路径。完整来源、扫描结果和映射留在执行上下文；工具输出只保留本轮变化、失败项及下一步需要的局部信息，避免重复打印整份资料/DOM导致上下文膨胀。

解析准备优先于任何普通字段写入：

```json
{"serverName":"resume","attachmentId":"resume-pdf","mode":"upload_if_missing","attachments_only":false}
```

将以上参数交给 `prepare_resume_form`。用户明确禁止上传/重传时才改为 `existing_only`。附件 ID 和服务器有变化时以本次工具与附件索引为准。

- 用当前区域的回执、文件名和 `filesAssigned` 判断该区是否尝试过。已接收或已赋值但回执不明的同一区只观察，不重复赋值；失败不等于未上传。
- `ready:false` 与页面仍在上传/解析分别判断。有明确运行中证据时有限等待/观察，不同时启动牛客；限时后仍在运行就记录并跳过牛客阶段，继续其余可操作内容，解析引发的新变化重新定位后核对。没有运行中证据时，不把回执未知变成等待门槛。
- 首次未定位/歧义且尚未赋值时，从返回候选或扫描的用途选择已观察的 `elementId`，在牛客前定向尝试。不要因“PDF 未确认”停止填写。
- 顶部解析、独立正式简历、头像、其他附件分别判断。解析区成功不能代替正式附件；正式附件使用 `ensure_resume_attachment`，头像使用 `upload_attachment`。默认 PDF ID 已知时，专用工具自行获取资源，不额外重复下载。
- 文件传递交给专用代码工具。不打开系统文件选择器，不让模型自行拼本地路径、资源 URL、base64 或文件字节上传。

## 3. 核对解析，再尝试一次牛客

用 `scan_resume_form` 与最新来源核对 PDF 回填：先看经历归属、身份、日期、职位及正文，再做必要局部清理。

- 根据 `classificationRules` 的别名与内容识别记录，日期作为辅助和冲突证据；日期误解析不能抵消已经确认的归属。公司＋职位＋日期或项目名称＋日期用于绑定来源与页面，禁止按全页 input 序号或网页 `recordIndex` 猜来源索引。
- 清理明确误分类/重复记录前，保留来源路径与原内容，确认可在正确栏目恢复；只移除错误位置，保留正确字段与附件。身份不明或可能由用户新增的内容不覆盖。
- 解析核对后调用一次 `run_nowcoder_fill`。面板打开失败、工具失败或超时均继续主填；同一文档不再次点击牛客，也不强行切窗口找插件。
- 牛客一旦开始，不能再运行 PDF 解析。后续仅补明确独立、不会触发解析的正式附件；牛客云端旧资料不覆盖本轮 MCP 最新来源。

## 4. 按来源清单补齐整表

牛客后扫描，建立“来源记录 → 页面记录 → 字段”的映射，依次处理全部有内容的适用栏目。`recordInventory` 保留原始数组索引；只填首条经历不算完成，未挂载或折叠不等于不适用。

- 先新增缺失的来源记录，批量填写全部明确文本，再处理日期、下拉等特殊控件。`interact_elements` 每批最多 30 项；批次中途会改变结构的动作与依赖它的新字段分开执行。
- 原值优先用叶子 `sourcePath`，保留 `0` 和 `false`。日期粒度、选项或组合正文确需转换时只传有依据的 `value`，并记录映射依据；不要同时传与原值不同的 `value` 和 `sourcePath`。
- 下拉报“找不到选项”时，先在一个样本读取真实枚举、核对语义，再决定转换或延后；不先轮换点击方式、不把同一不匹配原值在所有页面试一遍。已展开且能定位有据选项时直接点击该选项，不重复开关。仅复用已证实转换，不把能力等级升档或同渲染器的不同公司枚举当成等价。
- 职位不是部门。结束日期已知就不能勾“至今”。正文从原始来源组合，不凭扫描截断预览判断全文，不把工作内容复制为新增项目。
- 非空也要对照来源。本轮 PDF/牛客造成的已确认误填按最新来源局部修正；无法判断是否人工补充的冲突保留待核对。未知或语义不明的项跳过，必填标记不授权编造默认值。期望薪资只对应期望薪资及单位，不映射当前工资。
- 新增、移除记录或页面重建后重新定位相关字段。下拉已展开就读取实际选项，调用方不重复点击开关；工具内部可关闭再重开同一控件，以确认 portal 归属。单次工具报错先读现场，避免执行已经发生的动作。
- 简单字段优先用批量结果和变化观察确认；只有阶段变化或整表复查才重扫。`observe_page` 的 `nextOffset` 非空必须读完相关范围，不能把第一页当整页。
- 批写部分失败时保留成功项，从结果中提取失败项和未执行项继续；不重发整批。新增一条记录后优先只定位受影响栏目，PDF/牛客广泛回填、文档变化或全表尾查才重建整表映射。
- 需要栏目保存的网站，在离开已填栏目之前执行明确的保存动作并读取结果，区分“页面有值”“保存已确认”“保存受阻”。保存因未知必填项失败时记录并继续独立可操作栏目，不等整份填写结束后才检查。保存不包含最终提交。
- Moka 年月、学历、学校/专业以及 Phoenix 下拉先用 `choose-option`；传扫描字段 ID，由工具定位同控件触发器，目标值使用已读真实枚举。精确匹配已选值不重开，失败才读当前弹层修对应项，不逐字段反复全页观察。菜单开合、Escape 和只读 CDP 不要求重核验整表；普通重写只核验受影响字段。只读 CDP 按实际工具 schema 读取普通 DOM；`throwOnSideEffect:true` 若拒绝 DOM getter，不把它误诊为连接或字段故障，不反复试同一表达式。
- 一次有依据的局部恢复后仍未取得来源正确的字段或记录成果，就记录该项并继续其他内容，不重复观察或扫描。结构/选项新证据不重置同阶段限时；全部普通内容完成后，集中难项使用第0节独立阶段窗口。PDF、牛客或记录重建引起的阶段变化仍需更新基线。
- 同模板的后续页面复用已证实的控件处理方法与来源转换，仍绑定当前元素并核对记录身份；不复制旧 ID、旧填写状态或未经确认的岗位答案。重复的工具不支持/枚举不匹配不在每家公司重新探索。
- 工具输出只取成功项数、失败项与下一步需要的局部信息；完整来源和快照在本轮复用。重复计数与格式比较用代码完成；确需委派独立的来源比对与离线映射时，只提供相关来源片段和差异，不复制整段任务历史。浏览器写操作由一个执行者串行完成，避免多个 Agent 争抢页面。

控件失败的最小恢复步骤和代码工具限制见 [恢复与试跑经验](references/recovery-and-evidence.md)。只有实际遇到这些情况时才读取对应部分。

## 5. Codex 做一次完整性尾查

直接模式不会替 Codex 自动追加模型尾查。单页主填后，或多页全部普通内容处理后，由当前 Codex 沿用完整来源和操作结果，先集中处理延后难项，再主动做一次完整性检查；保留补填能力，不只复述工具统计。

1. 全部普通内容已处理后调用 `resume_execution_phase({phase:"review"})`，使用本阶段独立诊断/恢复窗口，随后更新整表扫描，并读 `get_resume_progress.nextFields`。按 `locate_and_fill/read_back/recover_once` 补填、回读或有界恢复；`deferredFields` 保留未解决事实，不能因零失败而忽略。逐来源检查全部记录的身份、职位、日期、正文及成果；折叠/未挂载不等于不适用。
2. 补齐发现的有据遗漏，逐上传区检查附件。此时不重跑解析和牛客；无法补传的解析区明确列为遗漏，继续其他内容。
3. 结构稳定后用当前 ID 批量调用 `verify_form_fields`，每批最多 30 项，覆盖适用的已知字段，包括 PDF、牛客或人工已填且本轮未修改的字段。局部修改后只重核验受影响字段；局部不可核验不触发全表重写。只将 `status:verified`、`stable:true`、`satisfied:true` 的当前读值报告为核验通过；同时审查预期值是否真的有来源依据。
4. 字段调用自动关联来源叶子；组合正文、转换或不适用用 `record_resume_progress.records[].fields` 逐来源路径登记，注明依据。每批最多60条记录。完整性看 `sourceCoverage.complete/coverageSummary.recordFieldCoverage`，旧 `mapped_fields_verified` 只表示已登记子集；公司名通过不代表正文/日期齐全。登记不能自证成功，进度不输出个人原值。
5. 尾查中修正的字段重新局部核验。批量核验不可用、显示格式差异或旧统计残留记为未核验，不因计数追加修复；明确来源错误才在剩余预算内做一次局部修正与核验。当前页预算到时记录遗留并转下一页，全部页面集中难项与检查结束后统一交付；不因计数不齐追加整表循环。

检查延后清单时利用本轮已有回读判断字段是否已由解析/人工填好；格式不同但已有等价证据就保留，证据不足记未核验，不另开检查链路或重写。分类文字的点击不证明最终 radio/checkbox 已选择；已选状态也不单独证明组合地址、所属记录和保存结果都正确。

不要把“8 个写过的字段全通过”说成“整份简历填完”。完整性同时需要来源记录覆盖、适用字段回读和各附件区状态。

## 6. 结束与交付

调用 `browser_end_task` 释放上下文，保留网页内容。最终简述：已填模块及记录数、资料未知/填写失败/尚未处理、附件接收与解析状态、页面是否提交。页面回读不证明服务端保存，未经实际回执不标记已投递。

用结束工具返回的 `modelCalls/toolCalls` 报告该上下文消耗；`modelCalls:0` 仅表示 Pagent 独立聊天模型未调用，Codex 与牛客成本另计。多上下文分别累计，不只报最后一页计数。临时核验快照、调用日志和截图默认不落盘；确需保存时，仅放当前用户私有的系统临时目录（Windows：`%TEMP%` 下禁止继承、仅当前用户与 SYSTEM 可访问的子目录；POSIX：目录 700、文件 600），不放代码目录、`data/`、skill 或 Git。

多页任务按初始完整页面队列逐页汇总，包括零写入、未轮到及不可操作页面；页面总数和来源覆盖分母不能只取成功处理的页面。报告实际耗时、已覆盖/应覆盖记录数、延后项数及主要卡点。必要时区分准备、主填、尾查和连接等待的时间；以实测说明优化效果，不编造目标达成率或节省比例。来源覆盖与字段核验分别报告，避免零失败但大量未处理的假完整。

局部附件、控件、回执、记录及核验失败都继续其余内容；用户停止、页面关闭、登录失效或页面实际无法操作时才停止该页。默认不点击最终提交、代接受新法律条款或扩大操作范围；已有明确授权按本次任务执行，不重复询问。

完成本轮操作并交付结果后，如果该填写流程踩坑较多，但处理步骤具有稳定、可模板化复用的规律，简述值得复用的环节，并询问用户是否要精炼成可复用 SOP、模板或 skill 经验；用户同意后再整理。常规填写不额外询问，不在操作中途打断任务，也不把一次偶发故障固化成通用规则。
