# 简历填写：固定前置、模型补齐、一次尾查

运行时按 PDF → 解析核对 → 牛客补充填写 → 整表扫描 → 模型补齐 → 一次尾查执行。解析核对先修正有明确依据的误解析，避免牛客在错误记录上继续填；牛客之后仍检查内容与最新资料是否一致。单项无法确认就记录原因，继续其余有依据的内容；未知资料留空，用户停止立即生效，不自动提交申请。

## 执行链路

1. `prepare_resume_form` 使用已配置简历 MCP 的 PDF，尝试上传并有限等待回执与表单稳定。上传与否由当前页面各区的回执/赋值证据决定；“补充填写”或“已上传”不禁传，缺附件优先上传，已有回执复用。仅用户明确禁止上传/重传时用 `existing_only`，历史限制按申请页隔离。顶部解析区和独立正式附件区分别检查。
2. 模型解析核对先读取本轮最新 `get_resume compact:true`，再用 `scan_resume_form` 对照整表。前置控件未定位或歧义时，可根据页面语义选择 elementId 调用 `prepare_resume_form` 优先补传未尝试的解析区，再核对解析结果。依据 `classificationRules` 的别名、归属与来源路径识别误分类、重复记录和错配字段：先确认栏目、名称/别名和内容，日期作为辅助及冲突证据，不能因解析日期错误而保留已确认的误分类。只移除错误记录或清理错误字段，正确公司、学校、日期及 PDF、头像保留；不依据序号清空，也不把未知记录直接判错。归入实习时采用 MCP 实习日期。
3. 解析核对最多 8 次模型调用、90 秒，不提供自由脚本、通用上传或导航工具；提供受控 `prepare_resume_form` 和 `ensure_resume_attachment`，由页面端复用本区已有文件，避免重复赋值。空回复、工具失败或阶段限额均继续后续。到期后拒绝排队和迟到的工具，传递阶段中止信号以阻止注入准备后的迟发 DOM 命令；已经发出的结构化操作等待实际返回后才启动牛客，避免清理和回填交叉执行。用户停止直接结束，不等待在途调用，也不会启动牛客。工具原始结果及完整模型消息继续传给后续阶段，不把未确认的调用当成功或自动重删。
4. `run_nowcoder_fill` 检查牛客面板。面板缺失或已关闭时，调用本地简历 MCP 的 `resume_open_nowcoder_panel` 尝试打开一次；已打开则直接点击“补充填写”，有限等待插件结果。成功、失败、超时都记录为工具事件；点击成功不代表整份表单已填完。
5. `scan_resume_form` 读取全部栏目、记录和字段，保留错误及折叠/未挂载的覆盖提示。模型沿用本轮最新来源补齐普通字段及缺失记录；牛客可能仍使用旧在线简历，非空不等于正确，必须再核对归类、职位、日期和职责，修正本轮 PDF/牛客造成的已确认冲突，不修改牛客云端资料。复杂控件局部失败则记录后继续。模型不再获得顶部解析与牛客工具；仍可用 `ensure_resume_attachment` 补明确独立的非解析简历附件，工具不能写解析区、头像或通用其他附件。
6. 主填首次结束后，运行时沿用完整原始模型/工具消息追加唯一一轮尾查。模型用 `scan_resume_form` 更新整表清单，补齐遗漏并独立回读，包括牛客填入且本模型未修改的字段。不得只重复摘要，不重新执行解析或牛客。尾查再次检查独立正式附件，缺失时可定向补传。最终模型简述补齐模块、失败与未处理原因，运行时追加工具计数。尾查空回复明确记为未完成，保留结果而不追加第三轮重试。

## 来源与核验

牛客 1.0.5 没有跨扩展打开接口，首次注入需要它的工具栏动作。本地打开工具只支持 macOS 上已处于前台的 Google Chrome：检查当前页 URL 与 Pagent 目标相同，在工具栏按名称找到唯一的“牛客网申助手”按钮，再执行一次 AXPress。它不激活窗口、不切换标签页、不导航，也不读取 Cookie 或扩展存储。脚本有绝对截止时间和 8 秒进程超时；URL 改变、按钮缺失、权限不足均返回明确状态并继续模型补齐。首次使用若 macOS 未授予自动化/辅助功能权限，需要用户在系统权限提示中授权；程序不会修改系统授权。固定动作不向模型暴露为可重复调用的普通工具。

`ResumeWorkflow` 仅缓存已读 MCP 的非空原始标量；`false` 和 `0` 保留，空值、对象以及页面文字不会成为可填事实。批量写入和核验可传字段级 `sourcePath`，工具使用本轮私有来源缓存取真实值，模型不必反复复制手机号等数据，也不能把 `[redacted-*]` 展示占位串当原值。

来源清单保留数组原始索引；基本信息、自我描述等非数组栏目各作为一项。带 `sourcePath` 的字段调用自动关联所属记录；需补充范围或不适用原因时，`record_resume_progress` 一次批量登记多条。两条来源记录指向同一网页字段会标记映射冲突，不会同时算通过。只有字段独立核验通过才能进入工具证据，登记本身不证明整条经历完整。

来源覆盖按每个非空叶子计算，`sourceFields/nextFields` 保留名称之外的职位、日期、正文等缺口，`deferredFields` 单列延后事实。`coverageSummary` 分别报告来源是否读全、记录字段是否覆盖、值是否核验；读取完整与零核验失败均不能推导填写完整。`record_resume_progress.records[].fields` 可登记组合正文的多个来源路径，独立核验后的文本必须包含相应事实才算覆盖。来源更新只清理受影响映射及过期事实，空值不入队，`0/false` 保留。

Codex直连先处理全部页面可直接填写的内容，再用 `resume_execution_phase({phase:"review"})` 集中处理延后难项并检查来源完整性。直接调用入口保留5分钟主填、3分钟review；两个阶段分别累计90秒/6次诊断与45秒/3次实际目标恢复，主填耗尽不阻断后续集中处理。普通定位、保存和首次核验不继承其他字段的失败状态；未写字段首次核验不可用不进入恢复。阶段切换保留主填缺项与总耗时，同阶段重绑不清零。调度和来源补漏仍由Codex负责。

扫描结果原样进入本轮页面覆盖上下文，不把折叠、空白或尚未挂载自动判断为不适用。Formily/UD、Phoenix、Moka 语义补足标签、必填标记和下拉实际选中值。Moka 通过 apply-block/fields 的结构区分栏目与重复记录，通过 sd-Input-display-value 读取年月等已选值，避免把空的搜索 input 当成空白表单。字段错误、日期范围错误、可见错误提示会使核验返回 `invalid`，即使显示文字正确也不能算通过。读取返回 `nextOffset` 时继续同一范围分页；页面新增记录或重建后重新定位。

MCP 结构化资料在 64,000 字符内完整保留；超过上限返回明确省略标记和栏目名，按栏目读取，禁止使用半截 JSON 填写。扫描对上传区分别返回用途、网站回执和本地赋值证据；顶部解析成功不代表底部简历附件已上传。PDF 接收回执与解析完成分别报告，未确认解析时不得声称已经解析，也不能在补填后再次触发解析覆盖。

## 验证范围

单测覆盖 PDF/解析核对/牛客/扫描顺序、最新来源规则、解析限额/超时和迟到工具隔离及失败继续、用户停止、牛客按钮名的上传意图、来源引用与脱敏回读、未处理记录和冲突映射、一次模型尾查。隔离端测使用真实裁剪的 Moka/中国电子云/度小满结构与合成数据，检查工具调用及填写结果；是否经过真实招聘站点验证须以当次端测记录为准，不将本地测试当作线上成功证明。
