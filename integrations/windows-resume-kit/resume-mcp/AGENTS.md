# 个人简历资料规则

- 本机 `data/resume.json` 是结构化来源。只使用本人的明确资料；未知、缺失或冲突事实留空，不编造默认值。仅有空值的栏目可省略。
- 每次任务通过 Resume MCP 读取最新来源与全部经历；先核对 PDF 解析，再补齐全部适用记录。经历以名称、职位和日期绑定，不按网页顺序猜来源。
- Codex 直接调用 Pagent MCP 编排浏览器，不启动 Pagent 独立聊天模型或配置聊天 API key。具体流程遵守已安装的 `pagent-resume-fill` 或 `pagent-boss-apply` skill。
- 附件索引为 `data/attachments.json`，原件放在 `data/attachments/`；默认附件 ID 为 `resume-pdf`、`resume-image`、`avatar`。文件值与 Token 由工具传递，不在对话中打印字节、认证头或 Token。
- 每项失败只延后该项，继续其他有来源的字段和经历。Windows 无法自动打开牛客工具栏面板时继续普通填写，不反复重试，不假称牛客已运行。
- 局部写入成功不等于保存或投递成功；分别核对保存回执、来源覆盖与页面读值，报告未处理项。没有明确授权不点击最终提交、发送消息或接受新法律条款。
- 简历、附件、Token、个人招呼语与投递记录只保存在本机受限目录，不写入 skill，不提交 Git，不放入分享包。临时资料默认不落盘；确需保存时放个人临时目录并限制访问。
